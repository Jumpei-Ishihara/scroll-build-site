# SPEC-03 セクション固定方式

作成日: 2026-11-16 / ステータス: Verified(2026-11-16、テスト 55 件、幅 1280px と 375px)。手でスクロールしたときの滑らかさと実機は未確認。工程と固定の長さ(S-03)、見出しの運び方(S-13)は [SPEC-04](04-小人がパーツを運ぶ.md) で置き換えた

関連: [SPEC-00 共通要件](00-共通要件.md) / [SPEC-01 案 C(旧方式)](01-案C-カーソルの中の人.md)

## 1. 変更の理由

旧方式(SPEC-01)は、ページ全体を縮小して「骨組み → 文字 → 色 → 仕上げ」を全セクションまとめて進めていた。
そのため、段階が変わるたびにカメラがページの下まで行って上に戻り、見る人は同じページを何度も上下に往復することになった。

新方式では次のようにする。

- ページは最初から実寸で表示する。編集ツール風の画面(ツールバー、レイヤー、プロパティ、選択枠、名前付きカーソル)は出さない
- セクションが画面に来たら、ページの動きを止める。その場でスクロールに合わせて、そのセクションだけが組み上がる
- 組み上がったら、ページの動きが再開し、次のセクションへ進む
- 画面は下へ進むだけで、上に戻らない

SPEC-01 のうち、ツール UI に関する要件(C-01〜C-05、C-13、段階の定義)は廃止する。SPEC-00 の COM-03(演出の長さ)と COM-04(固定の方法)は、この文書の内容で置き換える。

## 2. 用語

| 用語 | 意味 |
|---|---|
| 場面 | 1 回の固定で組み立てる範囲。画面 1 枚に収まる大きさで区切る |
| 固定 | ページの動きが止まり、スクロールが組み立ての進行に使われている状態 |
| 移動 | 固定と固定の間。ページがスクロールと同じ量だけ動く、通常のスクロール |
| 工程 | 場面の中の 4 つの作業。骨組み → 文字 → 色と画像 → 仕上げ |

## 3. 場面

| 番号 | 場面 | 組み立てる要素 |
|---|---|---|
| 1 | ヒーロー | ヘッダー、見出し、説明文、ボタン |
| 2 | できること | カード 3 枚 |
| 3 | 実績(前半) | 実績の見出し、実績 1、実績 2 |
| 4 | 実績(後半) | 実績 3、実績 4 |
| 5 | 問い合わせ | 問い合わせ、フッター |

実績は画面 1 枚に収まらないので、2 つの場面に分ける。

## 4. 要件

### 4.1 固定と移動

| ID | 要件 |
|---|---|
| S-01 | 編集ツール風の UI を表示しない。ページは常に実寸で表示する |
| S-02 | 場面が画面の中央に来たら固定する。固定中はページが動かない |
| S-03 | 固定の長さは、場面 1 つにつき画面の高さの 1.4 倍のスクロール量とする |
| S-04 | 移動中は、ページがスクロールと同じ量だけ動く |
| S-05 | 固定の開始と終了で、ページの位置が飛ばない(1px 以内) |
| S-06 | スクロールを進めたとき、ページが上方向に戻ることはない |
| S-07 | 場面が画面より高い場合は、場面の上端を画面の上端に合わせて固定する |

### 4.2 組み立て

| ID | 要件 |
|---|---|
| S-10 | 固定中、その場面の要素が「骨組み → 文字 → 色と画像 → 仕上げ」の順に進む |
| S-11 | 固定が終わる時点で、その場面の全要素が完成形になっている |
| S-12 | まだ固定に入っていない場面の要素は表示しない。組み上がった場面は完成形のまま残る |
| S-13 | 見出しは 1 文字ずつ増える(旧 C-11 を引き継ぐ) |
| S-14 | 逆方向にスクロールすると、同じ手順を逆にたどって分解される(COM-02) |
| S-15 | 組み上がった場面のリンクとボタンは操作できる。組み立て中の要素は操作できない |

### 4.3 操作

| ID | 要件 |
|---|---|
| S-20 | ページの先頭では「スクロールすると組み立てが始まる」ことを伝える案内を出す。スクロールを始めたら消す |
| S-21 | 進行の表示は、場面の数(5)だけ区切りを持ち、今の場面と工程の名前を出す |
| S-22 | 「完成形を見る」を押すと、全場面が完成形になり、固定のない通常のページに切り替わる。押した時点で見えていた位置を保つ |
| S-23 | 「もう一度組み立てる」を押すと、先頭に戻って最初から組み立てられる |
| S-24 | ページ内リンク(「実績を見る」など)を押すと、リンク先の場面が組み上がった位置へ移動する |

### 4.4 小人

| ID | 要件 |
|---|---|
| K-01 | 小人は名前ラベルやカーソルの矢印を持たず、自分でパーツを扱う。ヘルメットの色で見分ける |
| K-02 | 小人が画面にいるのは固定中だけ。場面の最初に画面の外から入り、作業が終わると出ていく |
| K-03 | 動作は、歩く、引っ張る(骨組み)、運ぶ(文字)、置く(色と画像、仕上げ)、手を振る。表示するコマは 1 つだけ |
| K-04 | 人数はデスクトップで 3 人以下、スマホで 2 人以下 |
| K-05 | 大きさは、デスクトップで高さ 32〜48px、スマホで 24〜32px(旧 C-25 を引き継ぐ) |
| K-06 | 最後の場面では、作業のあと出ていかずに手を振る |
| K-07 | 全場面が組み上がったあと、フッターの隅に 1 人が休憩している(旧 C-24 を引き継ぐ) |
| K-08 | スクロールが止まっている間は、待機の動きをする(旧 C-22 を引き継ぐ) |

### 4.5 引き続き適用する共通要件

COM-01、COM-02、COM-05、COM-06、COM-10〜12、COM-20〜23、COM-30〜33、COM-40〜42、COM-50〜54。

## 6. 実装の要点

| 項目 | 内容 |
|---|---|
| 固定の方法 | 固定中はページ全体(`#frame`)を `position: fixed` にして、表示位置の分だけ上にずらす。移動中は通常の流れに戻し、終えた固定の長さの分だけ下にずらす。境界で両者の位置が一致するので飛ばない |
| ページの高さ | 完成サイトの高さ + 固定の長さの合計。`#pin` の高さとして設定する |
| ライブラリ | 使わない。GSAP は削除した。スクロールイベントのたびに状態を計算して描画する |
| なめらかさ | 小人の位置と箱の広がりには 0.12〜0.14 秒の CSS の補間をかける。色や角丸は 0.32 秒 |
| 小人の位置 | 固定中はページが動かないので、画面に固定した層(`#crew`)に画面上の座標で置く |
| 再読み込み | ページの高さをスクリプトで決めるため、ブラウザ任せでは位置が復元されないことがある。場面と進み具合を `sessionStorage` に保存して復元する |
| 画面の大きさの変更 | 測り直して、同じ場面の同じ進み具合に戻す。スマホのアドレスバーの出入り(高さだけ 120px 未満の変化)では測り直さない |
| 完成形を見る | `done` モードに切り替え、固定と高さの上乗せをやめる。見えていた位置にスクロール位置を合わせる |

実装中にテストで見つけて直した点:

- 最後の場面の終わり(ページの最下部)で、手を振る小人とフッターの小人が同時に出ていた。全場面が組み上がった時点で作業中の小人は引き上げるようにした
- 再読み込みで先頭に戻っていた。上記の保存と復元を入れた
