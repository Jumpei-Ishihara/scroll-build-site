# SPEC-05 自動で組み立てる

作成日: 2026-11-17 / ステータス: Verified(2026-11-17、テスト 93 件、幅 1280px と 375px)。実際の画面での動きと、実機のトラックパッド・タッチ操作は未確認

関連: [SPEC-03 セクション固定方式](03-セクション固定方式.md) / [SPEC-04 小人がパーツを運ぶ](04-小人がパーツを運ぶ.md)

## 1. 変更の理由

SPEC-03 と SPEC-04 では、組み立ての進み具合をスクロール量で決めていた。見る人がスクロールし続けないと組み上がらず、速さもスクロールの仕方で変わっていた。

新方式では次のようにする。

- 組み立ては時間で進むアニメーションにする。1 つの場面は約 3 秒で組み上がる
- 1 回のスクロールで、次の場面へ移動する。着いたら組み立てが自動で始まる
- 組み立てが終わるまで、ページは固定する。その間のスクロールは受け付けない

SPEC-03 のうち、スクロール量で進める要件(S-03、S-04、S-14、S-20)と K-08 は廃止する。場面の区切り、小人の動作、パーツの運び方(SPEC-04)は変えない。

## 2. 用語

| 用語 | 意味 |
|---|---|
| 組み立て中 | 場面のアニメーションが再生されている状態。ページは固定され、スクロールを受け付けない |
| 移動中 | 次(または前)の場面へ画面が動いている状態。約 0.7 秒 |
| 待機 | 場面が組み上がり、次のスクロールを待っている状態 |

## 3. 要件

### 3.1 進み方

| ID | 要件 |
|---|---|
| A-01 | ページを開くと、最初の場面(ヒーロー)の組み立てが自動で始まる |
| A-02 | 1 つの場面の組み立ては 3.2 秒で終わる。進み具合は時間だけで決まる |
| A-03 | 待機中に下へ 1 回スクロールすると、次の場面へ移動し、着いたら組み立てが自動で始まる |
| A-04 | 組み立て中と移動中は、スクロール、スワイプ、キー操作を受け付けない。ページは動かない |
| A-05 | 1 回のスクロール操作で進むのは 1 場面だけ。トラックパッドの慣性で 2 場面進まない |
| A-06 | 待機中に上へスクロールすると、前の場面へ移動する。組み上がった場面はそのまま残り、組み立て直さない |
| A-07 | 組み上がった場面へ戻ってから下へスクロールしたときは、移動だけ行う |
| A-08 | 最後の場面が組み上がると、固定のない通常のページに切り替わる。以後は自由にスクロールできる |
| A-09 | ブラウザ本来のスクロールは、組み立てが全部終わるまで止める。ページの位置は演出側で動かす |

### 3.2 操作

| ID | 要件 |
|---|---|
| A-10 | マウスホイール、トラックパッド、タッチのスワイプ(40px 以上)、キー(↓ / PageDown / Space で次、↑ / PageUp で前)で操作できる |
| A-11 | 進行の表示には、組み立て中は場面と工程の名前、待機中は「スクロールで次へ」を出す |
| A-12 | 「完成形を見る」は、組み立て中でも押せる。全場面が完成形になり、通常のページに切り替わる(S-22) |
| A-13 | 「もう一度組み立てる」を押すと、先頭に戻り、最初の場面の組み立てが始まる(S-23) |
| A-14 | ページ内リンクを押すと、リンク先の場面へ移動する。途中の場面は完成形にし、リンク先がまだなら組み立てる(S-24 を置き換える) |
| A-15 | キーボードで、画面の外にある組み上がった場面のリンクにフォーカスが移ったら、その場面へ移動する |
| A-16 | 再読み込みしたとき、組み上がっていた場面は完成形で表示し、見ていた場面に戻る(COM-06) |

## 5. 実装の要点

| 項目 | 内容 |
|---|---|
| 進め方 | `requestAnimationFrame` で毎コマ、経過時間から進み具合を計算して描画する。画面が描画されていないときも止まらないよう、タイマーでも進める(`src/core/scroll.js`) |
| スクロールの止め方 | `html` に `locked` クラスを付けて `overflow: hidden` にし、ページ全体(`#frame`)を画面に貼り付ける。ホイール、タッチ、キーの入力は「次へ」「前へ」の合図としてだけ受け取る |
| 慣性の扱い | 組み立て中と移動中の入力は捨てる。終わった直後(組み立て後 0.4 秒、移動だけのとき 0.9 秒)は、前の入力から 0.12 秒以上空いたか、急に強くなった入力だけを新しい操作として受け付ける |
| 幅 | スクロールを止めている間もスクロールバーの分の幅を空けておく(`scrollbar-gutter: stable`)。通常のページに切り替えたときにレイアウトが動かない |
| 状態の計算 | 場面 k の進み具合 q から状態を求める関数(`compose`)は SPEC-03 のまま。時間で q を進めるようにしただけで、工程や小人の動きの計算は変えていない |
| 時間の変更 | `src/c/timeline.js` の `BUILD_MS`(組み立て)と `MOVE_MS`(場面の間の移動) |

実装中にテストで見つけて直した点:

- スクロールを止めるとスクロールバーが消えて幅が広がり、通常のページに切り替えた瞬間に位置が数 px ずれた。スクロールバーの分の幅を常に空けるようにした
