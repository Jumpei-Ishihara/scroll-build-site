# SPEC-10 技術選定

作成日: 2026-11-11 / ステータス: Draft(案 C・案 D+E の両方に適用する)

関連: [SPEC-00 共通要件](00-共通要件.md) / [SPEC-11 詳細設計](11-詳細設計.md) / [SPEC-20 デザイン設計](20-デザイン設計.md)

## 1. 選定の方針

1. 完成サイトは普通の HTML と CSS で成立させる。演出はその上に重ねる(COM-20、COM-23)
2. 依存を増やさない。ライブラリは「自作すると品質が落ちる部分」だけに使う
3. 見た目は進行度から一意に決まるようにし、テストで状態を直接確認できる構造にする(COM-01)

## 2. 選定結果の一覧

| 領域 | 採用 | 不採用とした候補 |
|---|---|---|
| ビルド | なし(静的ファイルをそのまま配信) | Vite、Astro |
| JavaScript の構成 | ブラウザ標準の ES モジュール | バンドル、TypeScript |
| フレームワーク | なし | React、Vue、Svelte |
| スクロール連動 | GSAP ScrollTrigger 3.15.1 | CSS のスクロール連動アニメーション、自作 |
| レイアウト変形 | 案 C: CSS transform のみ / 案 D+E: GSAP Flip | View Transitions API |
| 慣性スクロール | 使わない(ブラウザ標準のスクロール) | Lenis、Locomotive Scroll |
| 描画 | DOM + CSS + インライン SVG | Canvas、WebGL、Three.js |
| 小人(案 C) | インライン SVG のコマ切り替え | Rive、Lottie、スプライト画像 |
| コードの色分け(案 D+E) | 自作の簡易トークナイザ(HTML と CSS のみ) | Prism、highlight.js、Shiki |
| フォント | 開発中は Google Fonts。公開前に使用文字だけのサブセットを同梱 | 全文字の同梱、システムフォントのみ |
| アイコン | 自作のインライン SVG | アイコンライブラリ |
| テスト | ブラウザ上で実行する自作スイート(void-gate と同じ方式) | Playwright、Vitest |
| 配信 | GitHub Pages | Vercel、Netlify |

## 3. 判断の理由

### 3.1 ビルドなし、フレームワークなし

- ページは 1 枚で、状態は「進行度」1 つだけ。コンポーネントの再描画を管理する必要がない
- 案 D+E は「表示しているコードが本当にこのページを作っている」ことが核なので、変換や圧縮を挟まない方が嘘がない
- ファイル数は 20 本以下の見込みで、HTTP/2 配信なら分割したままで読み込み時間に問題は出ない
- 見直す条件: モジュールが 40 本を超える、または初回読み込みが COM-52(2 秒)を超えた場合は Vite を入れる

### 3.2 スクロール連動に GSAP ScrollTrigger を使う

比較した結果は次のとおり。

| 観点 | GSAP ScrollTrigger | CSS のスクロール連動アニメーション | 自作 |
|---|---|---|---|
| 画面の固定と解除 | 標準機能 | position: sticky と組み合わせて自分で組む | 自分で組む |
| ブラウザ対応 | 全ブラウザ | Chrome 115、Safari 26、Firefox 159 以降。Firefox は 2026 年 10 月に対応したばかり | 全ブラウザ |
| 1 文字ずつ打つ、行数を数えるなどの処理 | JavaScript で書ける | CSS だけでは書けない | 書ける |
| 画面幅の変更時の再計算 | 標準機能 | 自動 | 自分で組む |
| 転送量 | 約 45KB(圧縮前) | 0 | 数 KB |

- この企画は「文字を 1 文字ずつ増やす」「コードの宣言が打ち終わったら反映する」など、進行度をもとに JavaScript で状態を計算する処理が中心になる。CSS だけでは完結しない
- CSS のスクロール連動アニメーションは [web.dev の 2026 年 10 月のまとめ](https://web.dev/blog/web-platform-10-2026)で主要ブラウザすべてに対応したと報告されているが、Firefox の対応が直近のため、古い版の利用者が残る
- 補助としての利用は認める。進行インジケーターのバーなど、単純で壊れても困らない部分は CSS のスクロール連動で書いてよい

### 3.3 ライセンス

- GSAP は 2025 年から、ScrollTrigger と Flip を含めて商用利用も無料になっている([Webflow の発表](https://webflow.com/blog/gsap-becomes-free))
- 制限として「コードなしでアニメーションを作るツールに組み込む場合は許可が必要」という趣旨の条項があると報告されている。今回は Web サイトの演出に使うだけなので該当しない見込み
- 公開前に [GSAP の standard license](https://gsap.com/standard-license) の本文を確認する(未確認)

### 3.4 慣性スクロールを使わない

- スクロール位置と見た目を 1 対 1 に保つ(COM-01)には、ブラウザ標準のスクロールが最も確実
- 慣性スクロールのライブラリは、キーボード操作、ページ内検索、スクリーンリーダーとの相性で問題が出やすい
- なめらかさは、ScrollTrigger の scrub(スクロールに少し遅れて追従させる設定)で補う。遅延は 0.3 秒以内とする

### 3.5 DOM で描く(Canvas や WebGL を使わない)

- 完成サイトの実物の DOM をそのまま演出に使う。これにより、演出の終わりと完成サイトが構造上ずれない(C-13、DE-31)
- 動かす要素は多くても 100 個程度で、transform と opacity だけなら DOM で 50fps を保てる見込み(COM-50)
- [2026 年のトレンド記事](https://elements.envato.com/learn/web-design-trends)では 3D 表現が主流の 1 つとされているが、この企画の主役は「UI が組み上がる過程」であり、3D は目的に合わない

### 3.6 小人は SVG のコマ切り替え

| 観点 | SVG のコマ切り替え | Rive | Lottie |
|---|---|---|---|
| 追加の転送量(Rive と Lottie は記憶に基づく概算で未計測) | 数 KB | ランタイム 100KB 台 | ランタイム 200KB 台 |
| 制作に必要な道具 | テキストエディタ | Rive エディタ | After Effects |
| スクロールとの同期 | コマ番号を進行度から計算 | 可能 | 可能 |
| 動きのなめらかさ | コマ数に依存(4〜8 コマ) | 高い | 高い |
| 色やサイズの変更 | CSS で変えられる | エディタで再出力 | 再出力 |

- 小人は高さ 32〜48px と小さく、線画であれば 4〜8 コマで十分に動いて見える
- 外部の制作ツールに依存しないので、絵柄の修正をコードの変更だけで完結できる
- 見直す条件: フェーズ 3 で 1 か所作ってみて動きが硬く見えた場合は Rive を検討する

### 3.7 コードの色分けは自作する

- 対象は HTML と CSS だけで、表示するコードは自分たちで書いたものに限られる。汎用ライブラリの対応範囲は不要
- 色分けと「どこまで打ち終わったか」の判定は、同じ字句解析の結果を使う。ライブラリを使うと解析が二重になる
- 見込みの実装量は 100 行程度

### 3.8 フォント

- 日本語フォントは 1 書体で数 MB あり、そのまま同梱すると COM-51(1MB 以下)を満たせない
- 完成サイトの文章は固定なので、使用している文字だけを抜き出したサブセットを作れば、1 書体あたり 30〜60KB に収まる見込み
- 開発中は文章が変わるので Google Fonts から読み込み、文章が確定したフェーズ 4 でサブセットを作って同梱する
- 本文は端末に入っているフォントを使い、Web フォントは見出しと英数字に限定する
- 採用する書体は SPEC-20 で定める

### 3.9 テストはブラウザ上の自作スイートを続ける

- void-gate と同じ方式で、すでに `tests/run-all.js` と `tests/phase0.js` が動いている
- 進行度から状態を計算する関数を副作用なしで書く(SPEC-11)ので、状態の確認はブラウザ上の JavaScript だけで足りる
- 見た目の一致(C-13、DE-31 の 1px 以内)は、要素の位置と大きさを数値で比較する
- フレームレートの計測(COM-50)だけは自動化が難しいので、開発者ツールでの手動計測とする

## 4. 対応環境

| 環境 | 版 |
|---|---|
| Chrome、Edge | 最新版とその 1 つ前 |
| Safari(macOS、iOS) | 17 以降 |
| Firefox | 最新版とその 1 つ前 |
| 画面幅 | 375px 〜 1920px |

使用する主な CSS 機能は、カスタムプロパティ、Grid、clamp()、:has()、ネスト記法。いずれも上記の版で使える。

## 5. 未確認の事項とリスク

| 項目 | 状況 | 対応 |
|---|---|---|
| GSAP のライセンス本文 | 二次情報のみ確認 | 公開前に本文を読む |
| フォントのサブセット後の容量 | 見込み値。実測していない | フェーズ 4 で計測し、超える場合は書体を減らす |
| iOS Safari での画面固定のカクつき | 未検証 | フェーズ 1 の時点で実機確認する |
| 採用書体が Google Fonts で提供されているか | スタイルガイドで読み込みを確認する | SPEC-20 に結果を記載 |
