## 1. 設計の中心になる考え方

### 1.1 完成サイトの実物を演出に使う

演出用の模型を別に作らず、完成サイトの DOM そのものを縮小して「制作中の画面」として見せる。

- 演出の最後で縮小率が 1 になれば、それがそのまま完成サイトになる。模型と実物の差し替えがないので、切り替わりのずれが構造上起きない(C-13、DE-31)
- 完成サイトの HTML は最初から全部ある(COM-20)。「まだ置かれていない」状態は、CSS で隠しているだけ
- JavaScript が動かなければ、隠す CSS も縮小もかからず、完成サイトがそのまま表示される(COM-23)

### 1.2 状態は進行度から計算する

```
スクロール位置 → 進行度 p(0〜1) → 状態 = stateAt(p) → 描画 render(状態)
```

- `stateAt(p)` は副作用のない関数にする。同じ p なら必ず同じ状態を返す(COM-01)。前回の状態を参照しないので、巻き戻しと途中からの再読み込みが特別扱いなしで動く(COM-02、COM-06)
- `render(状態)` は前回の状態との差分だけを DOM に反映する
- テストは `SB.state` を読んで状態を直接確認する

### 1.3 時間で動かしてよい範囲

進行度が決めるのは「到達する状態」とする。次の 3 つだけは時間で動かしてよい。

| 対象 | 長さ | 理由 |
|---|---|---|
| 状態が切り替わるときの補間(色の変化、要素の移動) | 0.2〜0.4 秒 | 瞬間的に切り替わるとちらつく(DE-30) |
| スクロールへの追従の遅れ(scrub) | 0.3 秒以内 | ホイールの段差をならす |
| 待機中の動き(小人の揺れ、入力カーソルの点滅) | 繰り返し | スクロールを止めた画面が静止画に見えないようにする(C-22) |

どれも、スクロールを止めて 0.5 秒待てば、進行度から決まる状態に落ち着く。テストはこの落ち着いた状態を確認する。

## 2. ページ構造

```html
<body data-mode="build">          <!-- build: 演出中 / done: 公開完了 / static: 演出なし -->
  <div id="tool" aria-hidden="true" inert>
    <!-- ツール UI。案ごとに中身が違う。完成サイトより手前に固定表示 -->
  </div>

  <div id="pin">                  <!-- ScrollTrigger が固定する要素 -->
    <div id="frame">              <!-- 縮小と移動をかける要素 -->
      <div id="site">             <!-- 完成サイトの実物 -->
        <header>…</header>
        <main>…</main>
        <footer>…</footer>
      </div>
    </div>
  </div>

  <div id="controls">             <!-- 進行インジケーター、スキップ -->
  </div>
</body>
```

| 要素 | 役割 |
|---|---|
| `#pin` | 演出の間、画面に固定される。固定の長さは画面の高さ 5 枚分。固定が外れると `#site` が通常どおりスクロールする |
| `#frame` | `transform: translate() scale()` をかける唯一の要素。左上を基準に縮小する。演出中は高さを画面に合わせて切り取らず、縮小したページ全体がアートボードとして見える |
| `#site` | 幅は常に画面幅と同じ。縮小されてもレイアウトは変わらない |
| `#tool` | `position: fixed`。`inert` を付けて、キーボード操作と読み上げの対象から外す(COM-31) |
| `#controls` | `position: fixed`。ここだけは演出中も操作できる(COM-12) |

`data-mode` の切り替え:

| 値 | 条件 | 見た目 |
|---|---|---|
| `static` | JavaScript 無効、または「動きを減らす」設定 | ツール UI なし。完成サイトのみ(COM-23、COM-30) |
| `build` | 進行度が 1 未満 | ツール UI あり。完成サイトは縮小表示 |
| `done` | 進行度が 1 | ツール UI なし。完成サイトのリンクが操作可能になる(COM-22、DE-32) |

HTML には最初 `data-mode="static"` を書いておき、JavaScript が起動した時点で `build` に変える。こうすると、JavaScript が動かない環境では何もしなくても完成サイトが出る。

## 4. 共通モジュール

### 4.1 progress.js

公開する API(`window.SB`):

| API | 内容 |
|---|---|
| `SB.progress` | 現在の進行度(0〜1) |
| `SB.state` | 現在の状態。`stateAt(SB.progress)` の結果 |
| `SB.mode` | `'static'`、`'build'`、`'done'` のいずれか |
| `SB.onProgress(fn)` | 進行度が変わるたびに呼ばれる関数を登録する |
| `SB.setProgress(p)` | テスト用。進行度 p の位置へスクロールし、補間が落ち着くまで待って進行度を返す |
| `SB.stateAt(p)` | テスト用。スクロールせずに、進行度 p の状態を計算して返す |

ScrollTrigger の設定:

```js
ScrollTrigger.create({
  trigger: '#pin',
  start: 'top top',
  end: () => '+=' + window.innerHeight * 5,   // COM-03
  pin: true,
  scrub: 0.3,
  invalidateOnRefresh: true,                   // COM-42: 幅が変わったら再計算
  onUpdate: self => update(self.progress),
});
```

### 4.2 stages.js

段階は配列で定義し、境界の値を 1 か所にまとめる。

```js
export const STAGES = [
  { id: 0, name: '白紙',     from: 0.00, to: 0.08 },
  { id: 1, name: '骨組み',   from: 0.08, to: 0.28 },
  { id: 2, name: '文字',     from: 0.28, to: 0.48 },
  { id: 3, name: '色と画像', from: 0.48, to: 0.68 },
  { id: 4, name: '仕上げ',   from: 0.68, to: 0.85 },
  { id: 5, name: '公開',     from: 0.85, to: 1.00 },
];
export function stageAt(p)   // → { stage, local }  local は段階内の進み具合(0〜1)
```

段階の名前は案ごとに差し替える。スマホで段階を減らす場合(COM-41)は、同じ形の別の配列を使う。

### 4.3 frame.js

`#frame` の縮小率と位置を、進行度と画面の大きさから計算する。

| 進行度 | 縮小率 | 位置 |
|---|---|---|
| 0 〜 0.85 | 案ごとの「作業中の縮小率」で一定 | ツール UI の作業領域の中央上寄せ |
| 0.85 〜 1.0 | 作業中の縮小率から 1 へ補間 | 作業領域の位置から画面の左上(0, 0)へ補間 |

作業中の縮小率 = 作業領域の幅 ÷ 画面幅 × 0.9。作業領域は、案 C ではキャンバス、案 D+E ではプレビュー枠。

公開の補間には、動き出しがゆるく終わりもゆるいイージングを使う(SPEC-20 の `--ease-publish`)。

### 4.4 controls.js

| 部品 | 動作 |
|---|---|
| 進行インジケーター | 段階の数だけ区切りのある横棒。現在の段階名を表示(COM-05) |
| スキップ | `<button>`。押すと進行度 1 の位置へ移動する。`scrollTo` の `behavior` は `'auto'`(瞬時)とする(COM-10) |
| やり直し | フッター内の `<button>`。ページ先頭へ移動する(COM-11) |

## 5. 完成サイト側の描画の共通ルール

演出中に完成サイトの要素を隠したり仮の姿にしたりする指定は、すべて `build.css` に書き、`body[data-mode="build"]` の下でだけ有効にする。完成サイト本来の CSS(`site.css`)には演出のための指定を混ぜない。

要素の状態は `data-` 属性で表す。JavaScript は属性を書き換えるだけにし、見た目は CSS が決める。

| 属性 | 値 | 意味 |
|---|---|---|
| `data-b` | `hidden` / `box` / `text` / `color` / `final` | その要素がどこまで組み上がったか |
| `--b` | 0〜1 の数値(CSS カスタムプロパティ) | 現在の状態の中での進み具合。箱が広がる途中などに使う |

## 6. 案 C の設計

### 6.1 手順のデータ(timeline.js)

演出の内容は、手順の配列として宣言的に書く。コードの分岐で演出を作らない。

```js
export const STEPS = [
  { id: 'box-header', stage: 1, from: 0.00, to: 0.15, target: '[data-key="header"]',
    action: 'box', cursor: 'a' },
  { id: 'box-hero',   stage: 1, from: 0.12, to: 0.40, target: '[data-key="hero"]',
    action: 'box', cursor: 'b', kobito: 'pull' },
  { id: 'type-h1',    stage: 2, from: 0.00, to: 0.45, target: '[data-key="hero-title"]',
    action: 'type', cursor: 'a', kobito: 'carry' },
  // …
];
```

| 項目 | 内容 |
|---|---|
| `stage`、`from`、`to` | どの段階の、段階内のどの範囲で実行するか。範囲は重なってよい(複数のカーソルが同時に作業する) |
| `target` | 対象の要素。`data-key` で指定する |
| `action` | `box`(箱を引く)、`type`(文字を打つ)、`fill`(色を入れる)、`image`(画像を入れる)、`polish`(角丸と影)、`comment`(コメントピン)、`publish` |
| `cursor` | 担当するカーソル。`a`、`b`、`c` |
| `kobito` | 小人の動作。省略時は `hang`(ぶら下がる) |

手順は 25〜35 個の見込み。スマホ用は `mobile: false` を付けた手順を除外して使う。

### 6.2 状態(state.js)

`stateAt(p)` が返す形:

```js
{
  stage: 2, local: 0.31,
  elements: {                       // 完成サイトの各要素
    'hero-title': { b: 'text', t: 0.69, chars: 9 },   // t は状態内の進み具合
    'card-1':     { b: 'box',  t: 1 },
    // …
  },
  layers: ['header', 'hero', 'hero-title', 'card-1', …],   // 配置済みの要素。C-01
  cursors: {
    a: { x: 0.42, y: 0.31, target: 'hero-title', kobito: 'carry', frame: 3 },
    b: { x: 0.70, y: 0.55, target: null,         kobito: 'hang',  frame: 0 },
  },
  selected: 'hero-title',           // 選択枠を出す要素。C-02
  props: { color: '#16150F', radius: 0, padding: 0 },      // C-03
  toolVisible: 1,                   // 1 → 0 で退場。C-05
  frame: { scale: 0.52, x: 268, y: 72 },
}
```

カーソルの座標は、作業領域に対する割合(0〜1)で持つ。描画時に画面上の位置へ変換する。

カーソルの位置の決め方:

1. その進行度で実行中の手順があれば、対象要素の位置(箱の右下の角、打っている文字の右端など)
2. 手順と手順の間は、前の手順の終点と次の手順の始点を補間する
3. 担当する手順がもうない場合は、作業領域の端で待機する

対象要素の位置は、起動時と画面幅の変更時に 1 回だけ計測して保存する。`stateAt` の中では DOM を読まない。

### 6.3 各 action の描画

| action | 実装 |
|---|---|
| `box` | 要素に `data-b="box"` を付ける。`build.css` で中身を透明にし、灰色の背景と破線の枠を出す。`--b` で `clip-path` を左上から右下へ広げる(C-10) |
| `type` | 起動時に見出しを 1 文字ずつ `<span>` に分ける。元の文章は親要素の `aria-label` に残し、分けた `<span>` は読み上げ対象から外す。表示する文字数を `chars` で指定する(C-11) |
| `fill` | `data-b="color"` を付ける。演出中、色は CSS カスタムプロパティ経由で指定しておき、灰色から本来の色へ切り替える。セクション単位で順に実行する(C-12) |
| `image` | 画像の枠に対角線入りの仮表示を出しておき、`clip-path` で本来の絵を出す |
| `polish` | 角丸と影のカスタムプロパティを 0 から本来の値へ補間する |
| `comment` | ツール UI 側にピンを出し、消す |
| `publish` | `toolVisible` を 1 から 0 へ。`frame` を縮小率 1 へ |

### 6.4 小人(kobito.js)

- 1 人の小人は 1 つのインライン SVG。動作ごとのコマを `<g data-pose="carry-2">` のようにグループで持ち、表示するグループを 1 つだけ切り替える
- コマ番号は進行度から計算する: `frame = floor(手順内の進み具合 × その手順の総コマ数) % 動作のコマ数`
- 待機の動き(C-22): スクロールが 150 ミリ秒止まったら `body` に `data-idle` を付け、CSS アニメーションで小さく揺らす。スクロールが再開したら外す
- 巻き戻し(C-23): スクロールの向きが逆のとき、`kobito` を強制的に `hang` にする。向きは状態ではなく描画側で扱う(見た目の到達状態には影響しないため)
- 色: 線は `currentColor`、ヘルメットは担当カーソルの色

### 6.5 ツール UI の描画(render-tool.js)

| 部品 | 描画の元になる状態 | 更新の方法 |
|---|---|---|
| レイヤーパネル | `layers` | 起動時に全行を作っておき、`layers` に含まれる行だけ表示する。行の追加と削除で DOM を作り直さない |
| 選択枠と寸法ラベル | `selected` と、その要素の計測済みの位置 | 1 つの要素を使い回して位置と大きさを変える |
| プロパティパネル | `props` | 値の文字列を書き換える。色は `getComputedStyle` ではなく、手順のデータから求める |
| カーソル | `cursors` | `transform` で移動 |

## 7. 案 D+E の設計

### 7.1 コードの出どころ

エディタに打たれる CSS は、`src/styles/site.css` のファイルそのものとする(DE-01)。

1. 起動時に `site.css` を `fetch` で文字列として読み込む
2. `<link rel="stylesheet" href="site.css">` を無効にする(`disabled = true`)
3. 進行度に応じて、打ち終わった部分だけを集めた CSS を `<style id="live">` に書き込む
4. 進行度 1 で `<style id="live">` を空にし、`<link>` を有効に戻す

JavaScript が動かない場合は手順 2 が実行されないので、`site.css` 全体が普通に適用される(COM-23)。

`site.css` は 60 行以内に収める(DE-05)。リセットや書体の読み込みなど、見せても意味が伝わらない指定は `site-base.css` に分け、こちらは最初から適用しておく。エディタには「site-base.css ほか◯行」と表示する。

### 7.2 台本の書き方

段階の区切りとチャットの発言は、`site.css` の中のコメントで指定する。コードと台本が同じファイルにあるので、ずれが起きない。

```css
/* @stage 2 | カードは横に並べたいです | 並べました */
.cards {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  gap: 24px;
}

/* @stage 3 | もう少し明るい印象に | 色を入れました */
body {
  background: var(--paper);
  color: var(--ink);
}
```

形式: `/* @stage 段階番号 | 依頼者の発言 | 制作者の返答 */`

このコメントはエディタには表示しない。段階 1(HTML)だけは CSS ではないので、`script.js` に HTML の抜粋と対応する要素の `data-key` を書く。

### 7.3 字句解析(tokenize.js)

`site.css` の文字列を、次の単位に分ける。

| 種類 | 例 | 色分けの分類 |
|---|---|---|
| `selector` | `.cards` | セレクタ |
| `brace` | `{`、`}` | 記号 |
| `property` | `display` | プロパティ |
| `value` | `grid` | 値 |
| `punct` | `:`、`;` | 記号 |
| `comment` | `/* … */` | コメント |
| `space` | 空白、改行 | なし |

各単位は、ファイル内での開始位置と終了位置を持つ。さらに、宣言ごとに次の情報をまとめる。

```js
{ selector: '.cards', property: 'display', value: 'grid',
  ruleStart: 120, start: 131, end: 145, stage: 2 }   // end はセミコロンの次の位置
```

対応する構文は、セレクタ、宣言、コメント、`@media` の 1 階層まで。それ以外は `site.css` に書かない。

### 7.4 状態(state.js)

```js
{
  stage: 2, local: 0.5,
  typed: 418,                       // 打ち終わった文字数
  tab: 'css',                       // DE-13
  caret: { line: 14, col: 22 },     // DE-10
  applied: [0, 1, 2, …, 11],        // 反映済みの宣言の番号。DE-02
  active: { selector: '.cards', property: 'gap' },   // 今打っている宣言。DE-14
  chat: [                           // DE-20、DE-22
    { who: 'client', text: 'サイトを作ってください' },
    { who: 'maker',  text: '承知しました' },
    // …
  ],
  toolVisible: 1,
  frame: { scale: 0.45, x: 704, y: 64 },
}
```

進行度から `typed` を求める方法:

- 各段階には、その段階で打つコードの範囲(開始位置と終了位置)が台本から決まる
- 段階内の進み具合のうち、最初の 10% は依頼者の発言の表示、最後の 10% は制作者の返答の表示に使う。残りの 80% で、その段階の文字数を均等に打つ
- `applied` は「`end` が `typed` 以下の宣言」。巻き戻すと `typed` が減り、宣言が外れる(DE-03)

### 7.5 反映(live-css.js)

- `applied` の宣言を、セレクタごとにまとめ直して CSS の文字列を作り、`<style id="live">` に書き込む
- 書き込むのは `applied` が変わったときだけ
- 配置が変わる宣言(`display`、`grid-template-columns`、`gap` など)を反映するときは、反映の前に GSAP Flip で各要素の位置を記録し、反映後に 0.3 秒で新しい位置へ動かす(DE-30)
- 色や影などは CSS の `transition` で補間する。`transition` の指定は `build.css` に書き、演出中だけ有効にする
- スクロールが速く、Flip の実行中に次の反映が来た場合は、実行中の Flip を即座に完了させてから次を始める

### 7.6 エディタ(editor.js)

- 起動時に、全文を色分け済みの `<span>` として生成しておく。1 文字ずつ DOM を作らない
- 表示は「`typed` 文字目まで」。打ち終わった単位はそのまま表示し、打っている途中の単位だけ文字列を切り詰める
- 入力カーソルは 1 つの要素を `caret` の位置へ移動させる
- 自動スクロール(DE-12): `caret.line` がエディタの表示範囲の下から 3 行以内に入ったら、エディタ内を `transform` で上へずらす
- 強調表示(DE-14): `active.selector` に一致する完成サイトの要素の位置に、枠を重ねて表示する。枠は `#tool` 側に置き、完成サイトの DOM には手を入れない

### 7.7 画面幅ごとの構成

| 幅 | チャット | エディタ | プレビュー | 作業中の縮小率の目安 |
|---|---|---|---|---|
| 1024px 以上 | 左 20% | 中央 30% | 右 50% | 0.45 |
| 768px 以上 1024px 未満 | エディタ上部に最新 1 件 | 左 40% | 右 60% | 0.54 |
| 768px 未満 | 下部バーに最新 1 件 | 下部バーに 2〜3 行 | 全面 | 1(縮小しない) |

スマホでは完成サイトを縮小せず、画面の高さから下部バーの高さを引いた範囲に表示する。

## 8. 性能の設計

| 方針 | 内容 |
|---|---|
| 計測は起動時と幅の変更時だけ | 要素の位置と大きさを保存しておき、スクロール中は DOM を読まない |
| 書き込みは差分だけ | 前回の状態と比べて、変わった属性だけを書き換える |
| 動かすのは transform と opacity | 例外は案 D+E の CSS 反映時。このときだけレイアウトの再計算が起きるが、宣言 1 つにつき 1 回に抑える |
| `#frame` を独立した描画層にする | `will-change: transform` を演出中だけ付ける |
| 画面外の要素 | 縮小表示でページ全体が見えるため、`content-visibility` は使わない |

## 11. 実装時の改訂(2026-11-12、案 C)

実装して分かったことに合わせて、次の点を設計から変えた。

| 項目 | 設計 | 実装 | 理由 |
|---|---|---|---|
| スクロールへの追従の遅れ | ScrollTrigger の `scrub: 0.3` | 進行度を 0.25 秒で追従させる処理を自前で持つ。両端(0 と 1)では遅らせない | `scrub` は紐付けたアニメーションにしか効かない。また、固定が外れる瞬間に遅れが残ると、縮小したままのページがスクロールしてしまう |
| ファイル構成 | `core/frame.js`、`core/controls.js`、`c/render-site.js`、`c/render-tool.js`、`c/cursors.js` | 枠の計算とカーソルは `c/state.js`、描画は `c/render.js` にまとめた。計測は `c/measure.js` に分けた | 1 ファイル 150 行前後に収まり、分けると行き来が増えるだけだった |
| 手順のデータ | 25〜35 個を手書き | 要素の一覧から等間隔に生成する(57 個) | 同じカーソルの手順が重ならない条件を、計算で保証できる |
| カメラ | 記載なし | ページが画面より長いので、作業中の高さに合わせて上下に移動する。ハルの作業を追う | 縮小してもページ全体は 1 画面に収まらない |
| カーソルの座標 | 作業領域に対する割合 | 画面上の座標(px) | 公開ボタンなど、ページの外にある目標を同じ形で扱える |
| 段階 3 の小人の見せ場 | 記載なし | 実績 4(朱色の図形)に色を流し込む | 暗い面の上では線画が見えにくい。小人には紙色の縁取りも付けた |
| `SB.setProgress` | 補間が落ち着くまで待つ | 待ったうえで、CSS の補間を強制的に終わらせる | 画面が描画されていない環境では補間が進まず、待つだけではテストが安定しない |
| GSAP Flip | 読み込む | 読み込まない | 案 C では使わない |

テストで見つかって直した不具合: 途中のスクロール位置で読み込むと、計測より先に更新が走って起動に失敗していた(COM-06)。固定の設定より前に計測するようにした。
