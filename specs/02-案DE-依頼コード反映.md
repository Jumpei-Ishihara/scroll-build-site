# SPEC-02 案 D+E「依頼 → コード → 反映」要件

作成日: 2026-11-11 / ステータス: Draft(案 D+E を採用した場合に適用する)

関連: [企画書](../企画書.md) / [SPEC-00 共通要件](00-共通要件.md)

## 1. 概要

画面を「チャット」「エディタ」「プレビュー」に分ける。スクロールすると、チャットに依頼が届き、エディタでコードが打たれ、プレビューのページにその場で反映される。
最後に「公開しましょう」のやり取りでチャットとエディタが片付き、プレビューが完成サイトとして全幅に広がる。

- 見せたい相手: Web 制作者、発注者
- 題材(仮): 架空の開発会社のサイト
- この案の核は「表示されているコードが、本当にこのページの見た目を作っている」こと
- 共通要件(SPEC-00)をすべて満たしたうえで、この文書の要件を追加する

## 2. 画面構成

### デスクトップ(幅 1024px 以上)

| 領域 | 位置と幅の目安 | 内容 |
|---|---|---|
| チャット | 左、20% | 依頼者と制作者のやり取り。新しい発言が下に追加される |
| エディタ | 中央左、30% | ファイルタブ(HTML、CSS)、行番号、打たれていくコード |
| プレビュー | 右、50% | ブラウザ風の枠の中に、組み上がっていくページ |

### タブレット(幅 768px 以上 1024px 未満)

- チャットをエディタの上に重ね、最新の発言 1 件だけを吹き出しで表示する
- エディタ 40%、プレビュー 60%

### スマホ(幅 768px 未満)

- プレビューを画面全体に表示する
- 画面下部に高さ 120px 程度のバーを置き、最新の発言 1 件と、今打たれているコード 2〜3 行を表示する

## 3. 段階ごとの要件

進行度の範囲は目安で、実装時に調整してよい。

| 段階 | 進行度 | チャット | エディタ | プレビュー |
|---|---|---|---|---|
| 0. 白紙 | 0 〜 0.08 | 「サイトを作ってください」 | 空のファイル | 真っ白 |
| 1. 構造 | 0.08 〜 0.28 | 「まず骨組みをお願いします」 | HTML の見出し、段落、リンクが打たれる | 装飾なしの文字が上から並ぶ |
| 2. レイアウト | 0.28 〜 0.48 | 「カードは横に並べたいです」 | 配置と余白の指定が打たれる | 要素が所定の位置に動く |
| 3. 色と文字 | 0.48 〜 0.68 | 「もう少し明るい印象に」 | 色と書体の指定が打たれる | 配色と書体が変わる |
| 4. 仕上げ | 0.68 〜 0.85 | 「ボタンを目立たせてください」 | 角丸、影、ホバーの指定が打たれる | 細部が整う |
| 5. 納品 | 0.85 〜 1.0 | 「いいですね、公開しましょう」 | ファイルが保存されて閉じる | チャットとエディタが退き、全幅の完成サイトになる |

## 4. 機能要件

### 4.1 コードと見た目の一致

| ID | 要件 |
|---|---|
| DE-01 | エディタに表示する CSS は、プレビューに実際に適用されている CSS と同じものとする。表示用と適用用を別々に持たない |
| DE-02 | CSS の宣言は、エディタ上で最後の文字(セミコロン)まで打たれた時点でプレビューに反映する。打ちかけの宣言は反映しない |
| DE-03 | 巻き戻すと、コードは末尾から 1 文字ずつ消え、宣言が不完全になった時点でプレビューからその指定が外れる |
| DE-04 | 進行度 1 の時点でエディタに表示されている CSS 全文を適用した結果が、完成サイトの見た目と一致する |
| DE-05 | エディタに表示するコードは、初心者が読める量に抑える。CSS は合計 60 行以内を目安とし、省略した部分がある場合は「ほか◯行」と表示する |

### 4.2 エディタ

| ID | 要件 |
|---|---|
| DE-10 | コードは進行度に応じて 1 文字ずつ打たれる。カーソル(縦棒)が入力位置に表示される |
| DE-11 | 構文の種類(タグ、プロパティ、値、コメント)ごとに色分けする |
| DE-12 | 入力位置が常に見えるよう、エディタ内を自動でスクロールする |
| DE-13 | 段階 1 は HTML タブ、段階 2 以降は CSS タブを表示する。切り替えは自動で行う |
| DE-14 | 今打っている宣言が影響するプレビュー上の要素を、枠線で強調する |

### 4.3 チャット

| ID | 要件 |
|---|---|
| DE-20 | 各段階の開始時に、依頼者の発言が 1 件表示される。段階の終了時に、制作者の短い返答(「できました」など)が 1 件表示される |
| DE-21 | 発言は専門用語を使わず、見た目の要望として書く(「グリッドにして」ではなく「横に並べたい」) |
| DE-22 | 発言の表示と消去は進行度に従う。巻き戻すと新しい発言から順に消える |
| DE-23 | 依頼者と制作者は架空の名前とアイコンで区別する |

### 4.4 プレビュー

| ID | 要件 |
|---|---|
| DE-30 | 指定が反映されるとき、変化を 0.2〜0.4 秒のなめらかな動きで見せる。位置の変化は瞬間移動させない |
| DE-31 | 段階 5 で、プレビューの枠が広がって完成サイトのレイアウトにつながる。切り替わりの瞬間に位置のずれやちらつきがない |
| DE-32 | プレビュー内のリンクとボタンは、公開完了まで操作できない。公開完了後は通常どおり操作できる |

### 4.5 フェーズ分割

| フェーズ | 範囲 | 完了の基準 |
|---|---|---|
| 1 | 3 列の骨格、段階 0、2、5。コードを打つ仕組みと反映の仕組み | DE-01 〜 DE-04 を満たし、白紙から公開までの流れが通る |
| 2 | 段階 1、3、4、色分け、強調表示、チャットの文面 | DE-10 〜 DE-32 を満たす |
| 3 | タブレットとスマホの構成 | 幅 375px と 768px で画面構成の要件を満たす |
| 4 | 動きを減らす設定、スキップ、性能調整 | SPEC-00 の全テストが通る |

## 5. 素材

| 素材 | 形式 | 量 |
|---|---|---|
| 台本 | 段階、発言、打つコードを並べたデータ(JSON など) | 6 段階分。チャット 12 件前後、CSS 60 行以内 |
| エディタとチャットの UI | HTML + CSS | 画像素材なし |
| 完成サイトの画像 | SVG または CSS で描く図形 | ヒーロー 1 点、カード 3 点 |

## 6. テスト観点

| テスト ID | 対象 | 確認内容 |
|---|---|---|
| T-DE-01 | DE-01, DE-04 | 進行度 1 でエディタの CSS 全文を取り出し、演出なしのページに適用した結果が完成サイトと一致する |
| T-DE-02 | DE-02 | 宣言の途中の進行度では対象要素の計算済みスタイルが変わらず、セミコロンまで進めた時点で変わる |
| T-DE-03 | DE-03 | 進行度を 0.6 から 0.4 に戻すと、段階 3 の色指定がプレビューから外れている |
| T-DE-04 | DE-05 | エディタに表示される CSS が 60 行以内である |
| T-DE-05 | DE-12 | 進行度 0.1 刻みで、入力位置がエディタの表示範囲内にある |
| T-DE-06 | DE-20, DE-22 | 各段階の開始時点での発言数が期待値と一致し、巻き戻すと減る |
| T-DE-07 | DE-31 | 進行度 1 の各セクションの位置と大きさが、演出なしで開いた完成サイトと 1px 以内で一致する |
| T-DE-08 | DE-32 | 進行度 0.5 でプレビュー内のリンクがクリックを受け取らず、進行度 1 では受け取る |
| T-DE-09 | 画面構成 | 幅 375px で下部バーが表示され、プレビューが全幅である。幅 1280px で 3 列である |

## 7. 範囲外

- 訪問者が自分でコードを書き換える機能
- 訪問者がチャットに入力する機能、AI との実際の対話
- JavaScript のコードを打つ演出(HTML と CSS のみ)
- 複数ページの組み立て(トップページ 1 枚のみ)
