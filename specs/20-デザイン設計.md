## 1. トレンド調査

### 1.1 2026 年の傾向

複数のトレンド記事で共通して挙げられていた傾向と、この企画での扱いをまとめる。出典の多くは制作会社やツール提供元の記事で、強調点は記事ごとに食い違う。大きな方向として読む。

| 傾向 | 内容 | この企画での扱い |
|---|---|---|
| 動く文字、特大の見出し | 文字の太さが変わる、スクロールで伸びる、1 文字ずつ現れる。見出しを画面いっぱいに大きく使う | 採用。見出しが 1 文字ずつ打たれる演出(C-11、DE-10)がそのまま該当する。見出しは最大 104px |
| 主役の色を 1 色に絞る | 多色を並べず、1 色を軸にシステム全体を組む | 採用。完成サイトのアクセントは案ごとに 1 色 |
| 鮮やかな色の復活 | 彩度の高い色、強いコントラスト | 一部採用。アクセント 1 色とカーソルの色に限って彩度を上げる。面全体には使わない |
| 手の跡、不完全さ | AI 生成物の均質さへの反動として、手描き、質感、わずかな不揃いを残す表現 | 採用。企画の核と一致する(後述) |
| ベントー型のレイアウト | 大きさの違うカードを箱詰めのように並べる | 採用。特徴カード 3 枚を 1.4 : 1 : 1 の不均等な幅で並べる |
| グリッドを崩す、非対称 | 12 分割の対称配置から外れる | 一部採用。ヒーローの見出しを左に寄せ、右を大きく空ける。全体の崩しはしない(組み上がる過程が読みにくくなる) |
| 目的のある動き | 装飾の動きは疲れる。反応を伝える動きだけ残す | 採用。動きはすべて「誰かが何かを置いた」という出来事に対応させる |
| 暗い配色を先に設計する | 開発者向け製品で特に増えている | 案 D+E のツール UI に採用。完成サイトは明るくして、エディタと見分けられるようにする |
| 最初から組み込むアクセシビリティ | コントラスト、フォーカス表示、動きを減らす設定を設計の初期から扱う | 採用。配色はコントラスト比を計算して決めた(5 章) |
| 3D、没入型 | WebGL による立体表現 | 不採用。主役は UI が組み上がる過程で、立体表現は目的に合わない |
| すりガラス表現 | 半透明のパネルで奥行きを出す | 不採用。ツール UI は線と面で構成し、輪郭をはっきりさせる |
| 過剰な装飾、コラージュ | 要素を重ねて密度を上げる | 不採用。組み上がる順序が追えなくなる |

受賞サイトの傾向として、1 つの個人ブログが「受賞作は複数の効果を混ぜず、1 つの強い見せ方に絞っている」「スクロールで物語を進める型が多い」と分析している。単独の観察なので参考程度だが、この企画の方向(スクロールで組み上がるという 1 つの見せ方に絞る)と合っている。

### 1.2 この企画とトレンドの接点

「手の跡が見える表現」が 2026 年の大きな流れとして複数の記事で挙げられている。背景として、AI が作った均質な見た目への疲れが指摘されている。

この企画は、サイトが「誰かの手で作られていく過程」を見せるものなので、この流れとそのまま重なる。デザインの軸を次のように定める。

**精密な道具と、手の跡。**

- ツール UI は精密に作る。線は 1px、数値は実際の値と一致させ、整然としている
- その中で動くもの(小人、打たれていく文字、依頼の言葉)には人の気配を残す
- 完成サイトは、整っているが均質すぎない。書体と余白で個性を出し、効果には頼らない

## 2. 共通のデザイン原則

| 原則 | 内容 |
|---|---|
| 3 つの層を見分けられるようにする | ツール UI、制作中のページ、完成サイトは、色の温度と書体で区別する。ツール UI は端末標準の書体と中立的な色、完成サイトは選んだ書体と性格のある色 |
| アクセントは 1 色 | 完成サイトで彩度の高い色を使うのは 1 色だけ。使う場所は、見出しの一部、番号、主要なボタンに限る |
| 文字で見せる | 画像や効果に頼らず、見出しの大きさと書体で画面を作る。画像が少なくても成立する |
| 余白は広く | セクション間は 96px 以上。本文の行の高さは 1.85 |
| 動きは出来事に対応させる | 何かが置かれた、反映された、公開された、のどれかに対応しない動きは入れない |

## 3. 共通の値

### 3.1 余白

4px 刻み。4、8、12、16、24、32、48、64、96 の 9 段階。

### 3.2 文字の大きさ

画面幅 375px から 1440px の間で連続的に変わる。

| 用途 | 375px のとき | 1440px のとき | 行の高さ |
|---|---|---|---|
| 特大の見出し | 44px | 104px | 1.08 |
| 見出し | 28px | 48px | 1.3 |
| 小見出し | 18px | 22px | 1.3 |
| 本文 | 15px | 17px | 1.85 |
| 補足 | 13px | 13px | 1.7 |
| ツール UI | 12px | 12px | 1.5 |

### 3.3 動き

| 名前 | 長さ | 動き方 | 使う場面 |
|---|---|---|---|
| snap | 0.18 秒 | 速く動き出して、すっと止まる | 選択枠が出る、レイヤーの行が増える、ボタンの反応 |
| apply | 0.32 秒 | やや速く動き出して、ゆっくり止まる | 色が入る、要素が新しい位置へ動く |
| publish | スクロールに連動 | ゆっくり動き出して、ゆっくり止まる | ツール UI が退き、ページが画面いっぱいに広がる |

- 弾む動き、行き過ぎて戻る動きは使わない。道具の精密さと合わない
- 例外は小人。小人だけは揺れや弾みを入れてよい。道具と人の対比を動きでも表す

## 4. 案ごとのデザイン

### 4.1 案 C(架空のデザインスタジオ)

**印象**: 紙とインク。落ち着いていて、手仕事の気配がある。

#### 配色

| 名前 | 値 | 用途 |
|---|---|---|
| paper | `#F6F3EC` | 地の色。わずかに黄みのある白 |
| paper-2 | `#ECE8DD` | カードなど、一段沈めた面 |
| ink | `#16150F` | 文字。真っ黒ではなく、わずかに温かい黒 |
| ink-2 | `#5C594F` | 補足の文字 |
| line | `#DCD7CA` | 罫線 |
| accent | `#E8421F` | 朱色。図形と特大の文字だけに使う |
| accent-text | `#C2330F` | 通常サイズの文字と、ボタンの地 |

#### 書体

| 用途 | 書体 | 理由 |
|---|---|---|
| 日本語の見出し | Shippori Mincho(太さ 700) | 明朝体の特大見出しは、線の強弱がはっきり出て、1 文字ずつ現れる演出が映える |
| 英字の見出し | Instrument Serif(斜体) | 見出しの中の英単語だけを斜体のセリフ体にして、アクセント色と組み合わせる |
| 本文 | Zen Kaku Gothic New | 明朝の見出しと合わせても硬くならない、やわらかいゴシック体 |

#### ツール UI(デザインツール風)

| 部品 | デザイン |
|---|---|
| キャンバス | `#E7E6E2` の地に 16px 間隔の点。完成サイトの紙色より冷たくして、フレームが浮いて見えるようにする |
| パネル | 白地、1px の罫線。影は付けない |
| 選択枠 | `#2747F5` の 1.5px の線、四隅に白い四角のハンドル、下に寸法ラベル |
| カーソル | 矢印と名前ラベル。色は 3 人で朱 `#D63A18`、青 `#2747F5`、緑 `#0B7F58`。名前は架空の短い名前(ハル、ミナト、ソラ) |
| 仮の箱 | `#DAD7CF` の塗り。これから置かれる箱は破線の枠だけ |
| 公開ボタン | 選択枠と同じ青の地に白い文字 |

ツール UI の色は青を基調にし、完成サイトのアクセント(朱)と分ける。朱が画面に現れるのは、段階 3 で色が入ってからになる。

#### 小人

| 項目 | 内容 |
|---|---|
| 絵柄 | 線画。線の太さ 1.8px、線の端は丸く |
| 大きさ | デスクトップで高さ 42px、スマホで 30px |
| 体 | 丸い頭、1 本線の胴と手足。目は点 2 つ |
| 色 | 線は ink。ヘルメットだけ担当カーソルの色で塗る |
| 位置 | カーソルの名前ラベルの下から、短いロープでぶら下がる |
| 待機 | ロープを支点に左右へ 5 度ずつ、2.4 秒周期でゆっくり揺れる。複数人は揺れのタイミングをずらす |

顔の表情や個体差は作らない。ヘルメットの色だけで誰の担当かが分かるようにする。

### 4.2 案 D+E(架空の開発会社)

**印象**: 明快で正確。暗いエディタと明るいページの対比。

#### 配色(完成サイト)

| 名前 | 値 | 用途 |
|---|---|---|
| paper | `#F4F6F8` | 地の色。わずかに青みのある白 |
| paper-2 | `#E8ECF0` | カードなど、一段沈めた面 |
| ink | `#0E1116` | 文字 |
| ink-2 | `#535B66` | 補足の文字 |
| line | `#D5DAE0` | 罫線 |
| accent | `#2747F5` | コバルト。文字にもボタンにも使える |
| signal | `#C6F432` | 黄緑。暗い面の上だけで使う強調色 |

#### 配色(ツール UI)

| 名前 | 値 | 用途 |
|---|---|---|
| tool-editor | `#0F1217` | エディタの地 |
| tool-panel | `#161A21` | チャットの地 |
| tool-line | `#252B35` | 罫線 |
| tool-text | `#D7DCE3` | 文字 |
| tool-text-2 | `#8792A0` | 補足、コメント |

コードの色分け:

| 分類 | 値 | 例 |
|---|---|---|
| セレクタ | `#E7C9FF` | `.cards` |
| プロパティ | `#8FB8FF` | `display` |
| 値 | `#C6F432` | `grid` |
| タグ | `#FF8A70` | `<h1>` |
| 記号 | `#9AA4B1` | `{`、`:`、`;` |
| コメント | `#8792A0` | `/* … */` |

値の色(黄緑)は、入力カーソル、選択中のタブの下線、プレビュー上の強調枠と同じ色にそろえる。「今ここを書いていて、ここに効いている」が色でつながる。

#### 書体

| 用途 | 書体 | 理由 |
|---|---|---|
| 見出しと本文 | IBM Plex Sans JP | 技術文書で見慣れた骨格で、太字の見出しに強さが出る。同じ系統に等幅書体があり、エディタと地続きに見える |
| コード、番号、小さな英字 | IBM Plex Mono | 上と同じ系統 |

見出しは字間を詰めて(-0.03em)、太さ 700 で組む。

#### ツール UI

| 部品 | デザイン |
|---|---|
| チャット | 依頼者の発言は左寄せで暗い吹き出し、制作者の返答は右寄せでコバルトの吹き出し。発言者は色付きの丸で区別する |
| エディタ | タブ(index.html、site.css)、行番号、色分けされたコード。今打っている行は地をわずかに明るくする |
| 入力カーソル | 黄緑の縦棒。待機中は点滅する |
| プレビュー | 上部に丸 3 つの簡素なブラウザ枠。地は明るく、暗いエディタとの対比を作る |
| 強調枠 | 今打っている宣言が効く要素を、黄緑の枠とセレクタ名のラベルで囲む |

## 6. 完成サイトの構成

両案とも同じ骨格にし、書体と色と文章で性格を分ける(COM-21)。

| セクション | 内容 | レイアウト |
|---|---|---|
| ヘッダー | 屋号、ナビゲーション 3 項目、問い合わせボタン | 左に屋号、右にナビゲーション。高さ 72px |
| ヒーロー | 特大の見出し(2 行)、説明文、ボタン 2 つ | 左寄せ。右側 3 割ほどを空ける。高さは画面の 8 割以上 |
| 特徴 | カード 3 枚。番号、小見出し、説明 | 1.4 : 1 : 1 の 3 列。1 枚目は白地に影、2 枚目は沈めた面、3 枚目は反転(暗い地) |
| 実績 | 3〜4 件。図形、名前、分類 | 2 列。画像は写真を使わず、色面と図形で構成する |
| 問い合わせ | 見出し、1 文、ボタン | 中央寄せ。地を ink にして反転させる |
| フッター | 屋号、著作権表記、「もう一度組み立てる」 | 1 行 |

見出しの文章(仮):

| 案 | 見出し | 補足 |
|---|---|---|
| C | 手で考え、pixel で仕上げる。 | 「pixel」だけ斜体のセリフ体、朱色 |
| D+E | 書いたとおりに、動く。 | 「動く。」だけコバルト |

屋号は未定。架空の名前を付けるときは、実在する会社と重ならないか確認する。

スマホ(幅 768px 未満)では、カードと実績を 1 列にし、ナビゲーションを屋号とボタンだけにする。

## 7. 段階ごとの見た目の変化

### 案 C

| 段階 | 完成サイト側 | 色 |
|---|---|---|
| 0 | 空のフレーム | 紙色のみ |
| 1 | 灰色の箱 | 紙色 + 灰 |
| 2 | 箱の一部が文字に置き換わる | 紙色 + 灰 + 墨 |
| 3 | 色と図形が入る | 朱が初めて現れる |
| 4 | 角丸、影が付く | 変化なし |
| 5 | 画面いっぱいに広がる | ツール UI の青と灰が消え、紙、墨、朱だけが残る |

色が段階を追って増えていき、最後にツール UI の色が抜けて完成サイトの 3 色だけになる。

### 案 D+E

| 段階 | 完成サイト側 | 色 |
|---|---|---|
| 0 | 真っ白 | 白 |
| 1 | ブラウザ標準の見た目の文字が並ぶ | 白 + 黒(標準の書体) |
| 2 | 配置が整う | 変化なし |
| 3 | 書体と色が入る | 選んだ書体に変わり、コバルトが現れる |
| 4 | 角丸、影、ボタンの装飾 | 変化なし |
| 5 | 画面いっぱいに広がる | 暗いツール UI が消え、明るいページだけが残る |

段階 1 と 2 は、あえて「飾りのない HTML」の見た目のままにする。段階 3 で書体が変わる瞬間が、この案でいちばん変化の大きい場面になる。

## 8. 確認結果

スタイルガイドを開発サーバーで表示して確認した。

| 項目 | 結果 |
|---|---|
| 書体の読み込み | 5 書体すべて Google Fonts から読み込めた(Instrument Serif、Shippori Mincho、Zen Kaku Gothic New、IBM Plex Sans JP、IBM Plex Mono) |
| 幅 1280px | 横スクロールなし。コンソールエラーなし |
| 幅 375px | 横スクロールなし。ツール UI の見本はパネルを省いた構成に切り替わる |

スタイルガイドのツール UI は静止した見本で、位置は固定値で置いている。スマホ幅ではカーソルの位置が文字とずれて見える。実装では要素の実際の位置から計算する(SPEC-11 の 6.2)。
